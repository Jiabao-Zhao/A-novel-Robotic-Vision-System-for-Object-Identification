Reviewed 2026-10-24 by robustness_capture. The converted-point-box proof, builder and kernel pass this conditional source review. The host wrapper is absent; compiled GPU behavior, performance, complete proxy behavior and deployment remain unvalidated. This review does not authorize GPU execution or production integration. ## Equality argument

The proposed bounds come from extrema of the exact converted FP32 descendant points, rather than from rounded original split planes. With a query below an interval, monotonic RN subtraction gives `RN(low-q) <= RN(p-q)`. Above it, sign symmetry gives `RN(q-high) <= abs(RN(p-q))`; inside it the bound is zero. Ordered nonnegative RN self-products and X+Y then Z additions preserve these inequalities. The resulting box score is therefore no greater than **the same rounded FP32 point score**, including gradual underflow and signed zero. This would not follow merely from an ordinary real-distance bound.

The existing original-coordinate cap of 2^60 bounds converted differences by 2^61; three squared differences remain below FP32 overflow. The argument requires the existing conversion/rounding guards and separate RN subtraction, multiplication and addition, without FTZ, DAZ, FMA or reassociation. Compiled PTX and runtime FP conditions still require their own review.

Pruning is strictly `lower > second`. Equality is retained because an equal-score smaller original point ID may change either position. Before two distinct IDs exist the second score is infinity, so no finite node is pruned. Distinctness concerns original IDs even when coordinates coincide. The local and shuffle merges retain each subset's lexicographic two smallest distinct `(score, original_ID)` items. Induction across visited leaves and safely discarded nodes gives the exhaustive FP32 pair. The old outward per-row certificate, original SciPy fallback and pinned CPU distance reconstruction can consequently stay unchanged, provided the host applies all old raw-result guards as well as the new invalid flag.

## Builder and kernel control

The builder checks bare nonperiodic 3D SciPy type, independent int32 point and node limits before data access, finite original coordinates, complete index permutation, root coverage, exact child partitions, nonempty leaves, node uniqueness, H<=63 and matching node count. Leaf containment and parent unions establish every ancestor's containment. Concatenated leaves equal the original index order. Returned numeric arrays are contiguous and read-only. Validation relies on the supported bare original SciPy tree; it is not a general untrusted graph parser.

Lane zero alone owns each warp's stack and global pair. Broadcast node/action values make loop control uniform. All active lanes enter each full-mask shuffle; padded-query returns are uniform under the exact 128x1x1 launch contract. Leaf invalid flags propagate through the reduction. For a binary DFS tree, the stack needs at most H+1 entries, so H<=63 fits 64 slots. Push capacity is checked. Node visits are bounded by the validated node count; node, leaf range and point indices are checked before dereference. Large point/node byte offsets use `long long`. The host must still enforce padded query IDs <=INT32_MAX and every actual buffer length, since the kernel cannot prove allocation sizes.

`invalid_out` uses logical OR and deliberately collapses internal reason bits into a boolean nonzero fallback flag. This is sufficient for correctness, but callers must not interpret it as distinct bit-coded diagnostics. Defensive row checks are additional safety; valid metadata must already be checked and frozen by the host.

The saved CPU receipt reports nine passing tests, 191 raw-pair parity rows, 21,366 evaluated point distances and 100,712 directed bound checks, with fixtures up to 129 points. Coverage includes duplicates/ties, signed zero, selected subnormal values, large offsets/cap neighbors, the H=63 stack boundary, forced overflow, malformed metadata and independent node-count preflight. The reviewer checked receipt/source hashes but did not rerun these tests. This evidence supports the source argument; it does not establish CUDA parity or throughput.

The final test preflight explicitly checks both x87 `fegetround()==0` and MXCSR rounding bits zero, plus FTZ/DAZ off. An earlier test version omitted the MXCSR rounding assertion although its recorded state already had those bits zero. The prior source and receipt are preserved under `pre_mxcsr_round_guard/`. The final receipt pins the existing SciPy and NumPy extension hashes.

## Remaining host-wrapper gates

1. Pin the original tree's data, order, bounds and opaque node state before/after flattening and at every query. Cache identity must additionally include all converted point, box, child, range and leaf-ID arrays. A point-buffer-only token is insufficient for tree metadata. Preserve immutable owner-thread buffers, exact original ID mapping and non-nested original fallback.
2. Enforce supported signature/type/layout, finite query and CAD cap, tree depth, int32 and padded launch bounds, all array lengths and cleanup. AND the invalid flag with all existing finite, nonnegative, ordered-score, distinct-valid-ID and certificate guards. Any unsupported or flagged row uses original SciPy semantics. Recheck pinned CPU distance bytes independently of raw search equality.
3. Budget **before** building/uploading. Builder peak memory includes point casts, permutation sort/arange, leaf gathers/copies and Python/list validation intermediates. Final device tree arrays require `16*n + 40*node_count` bytes; query plus five output arrays require 32 bytes/row, not the old exhaustive driver's 28. The new second-ID output must not accidentally reuse the old allocation formula. Maintain declared device/host caps and include lifetime caches and teardown.
4. Pin new wrapper/compiler/PTX and verify explicit RN/FTZ semantics. Conduct separately authorized bounded raw GPU comparison of both score bits and both original IDs, including invalid fallback; the old exhaustive kernel exposes only the first ID, so the second ID requires the independent exhaustive lexicographic reference. Then compare complete certified distance/index bytes to pinned SciPy and assess complete proxy timing, preparation and lifetime memory.

The kernel currently exports no traversal counters, so visited-node/point performance claims would need separately reviewed instrumentation. A valid adverse tree can still visit every point. No speedup or complete-bank runtime benefit follows from this source pass. No whole-fit replay, scientific dependency change or production integration is approved by this note.
