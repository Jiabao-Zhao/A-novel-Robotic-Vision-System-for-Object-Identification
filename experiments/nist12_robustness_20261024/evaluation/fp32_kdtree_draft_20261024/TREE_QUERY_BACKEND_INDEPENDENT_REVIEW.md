# Independent tree-backend source review

Status: the new wrapper passes this conditional source review for the intended `CertifiedKdTree.query` / `TreeQueryRuntime.top_two` path. It is eligible for a separately authorized isolated GPU audit once the current sole pilot has exited and its ownership barrier is released. No GPU execution, integration or whole-fit use is authorized by this receipt. Review used source reads and the author's saved fake-dependency test receipt; this reviewer did not import, compile or execute the wrapper, perform queries/fits or read new accuracy labels.

## Preserved result path

`CertifiedKdTree` subclasses the pinned existing `CertifiedQueryTree` and overrides only construction. Its query method, supported-signature checks, input normalization, per-row outward certificate, raw-output guards, selected CPU distance reconstruction, result shapes/dtypes and original SciPy fallback are the same inherited functions. The wrapper's point token becomes the existing complete original-tree fingerprint, rather than a point-only hash. The new runtime changes the raw FP32 search and its buffers; it does not alter the certificate or the original tree's point order.

The new raw engine returns the same first/second FP32 score arrays and first IDs expected by the inherited caller, plus flags. It additionally downloads the second ID and flags invalid/out-of-range or duplicate second IDs and reversed ID ordering at exact score ties. The inherited caller still requires finite, nonnegative, ordered scores, valid first IDs and a strict certified gap. A nonzero kernel flag or added second-ID flag therefore reaches original SciPy fallback; the row-valid mask is still ANDed with raw-result validity. No invalid flag is treated as absence or a fit failure.

Unsupported/deep/oversized trees are handled before the inherited recursive depth reader, leaving an unsupported wrapper whose original-call path retains arguments. The exact audited accelerated domain remains finite nonperiodic 3D trees and supported k=1 calls; unsupported calls retain the existing original fallback contract. Normal non-optimized Python execution, the pinned binaries/SSE41 dispatch, checked RN controls and immutable original inputs remain required conditions.

## Cache and resource accounting

Registration is owner-thread-only and bounded to 32 entries. Original data/order/bounds/opaque-node fingerprint is checked during registration and buffer lookup; cache hits additionally compare the FP64 snapshot and full flattened metadata signature. Flattened arrays are contiguous/read-only, and the complete points/boxes/children/ranges/leaf-ID content plus depth enters the signature. Separate pointer sets prevent an alternate CAD from overwriting a cached tree. Mutation disables the inherited accelerated path or raises into its original-call fallback.

Explicit retained numeric data is FP64 snapshot `24*n`, flattened points/IDs `16*n`, and metadata `40*nodes`, plus the existing metadata allowance. Device tree buffers use `16*n + 40*nodes`; shared query and five output buffers use **32 bytes/row**. The initial device check includes all these buffers, and subsequent cache fills add the full new tree to the already tracked allocation count. The inherited allocator independently enforces the device cap. This corrects the old exhaustive engine's 28-byte query/output row size.

The node count cap and independent point/node int32 limits precede conversion. Constructor admission checks its node-materialization allowance before accessing `tree.tree`; cache fill checks retained numeric, entry, transient and device budgets before flattening/session creation. `nodes*1024 + n*128 + retained` is a conservative host admission allowance, and `ru_maxrss` checks detect actual process high-water growth. These are **not allocator-enforced host limits** or a measured proof of peak RSS. A future bounded audit must retain headroom, measure actual peak/lifetime cache memory and stop on failed resource guards. Original trees/Python node views remain covered by the total process guard even though the numeric-cache counter is narrower.

## Source, launch and cleanup controls

The external review-file digest is checked, its approved flag and required source entries are required, all declared file hashes are checked, and the original proxy has a literal expected hash. Existing proxy initialization separately verifies the old proof/source receipts, pinned base/FP helper and installed numeric binaries. New source verification repeats immediately before and after compilation. The NVRTC and builtins libraries and options remain pinned; PTX inspection rejects FMA/MAD and FTZ arithmetic and requires RN operations and the expected entrypoint. The newly emitted PTX hash is recorded, not assumed already validated.

The intended launch supplies all 14 new arguments, exactly 128x1x1 threads and a one-dimensional grid with padded query IDs checked. Tree lengths and integer layout follow the validated builder. Review identified that the inherited `DriverSession.raw_top_two` would have been the old eight-argument launcher. The final new wrapper explicitly overrides it to raise `NotImplementedError` before any launch, with a focused fake test. Previous wrapper/test/receipt bytes are preserved in `pre_raw_entry_guard/`. A future raw parity harness must use the reviewed runtime's `top_two`, or obtain separate review for another tree-specific launcher.

Partial initialization closes its session even on a control exception. Allocation/upload/query errors in the intended inherited query path disable the runtime and close all tracked allocations. Override `disable` and `close` retain inherited cleanup receipts while clearing registrations and last second-ID references. A caller must still close the runtime in `finally`, including interrupts outside the initialization region; this is the existing wrapper lifecycle obligation. Cleanup errors must be inspected, not mistaken for successful teardown.

## Evidence and remaining gates

The frozen saved receipt reports 13 passing fake-dependency tests with two fake points and at most eight rows. The inspected tests check inherited query identity and pinned original-source hash, invalid and second-ID fallback, row-valid ANDing, CAD switching/mutation, host/device/entry/transient rejection before allocation, count/host preflight before node materialization, fixed argument/launch dimensions, byte accounting, partial initialization including KeyboardInterrupt, failed-allocation cleanup, cleanup-error preservation, review/PTX rejection and rejection of the inherited raw entrypoint. Original-tree query is a sentinel fake; actual SciPy queries, GPU/compiler calls, pose fits and accuracy reads are zero. Source and receipt hashes were independently checked; tests were not rerun by this reviewer.

No blocking source defect was found in this supported path. Outstanding gates are a separately authorized bounded runner with fresh resource/ownership clearance, actual compiled PTX/raw GPU parity for both score bits and both IDs, complete certified SciPy byte parity, measured host/device cleanup and controlled complete-proxy throughput. The core proof receipt remains separate and unchanged. No speedup, full-bank parity or production suitability follows from these fake tests alone.
